# 第二阶段视觉验收报告

检查日期：2026-07-20

## 检查范围

浏览器级自动回归覆盖以下视口：320、360、375、390、430、768、1024、1440px；覆盖首页、文章列表、样本列表和长文排版样本，共 32 组页面/视口组合。

另在本地开发预览中逐页检查：首页、文章列表、长文样本、专题、作品、关于、现在、404 和样本预览入口。页面主标题、主导航和页脚均正常显示，样本页具有“排版示例，不是正式文章”标记。正常页面返回 200，不存在的路径返回 404。

`clientWidth` 比设定视口少 15px 是测试浏览器保留的纵向滚动条宽度；所有尺寸均满足 `scrollWidth <= clientWidth`。

## 原横向溢出原因

新鲜启动的浏览器中，390px 未复现横向溢出；320px 稳定复现。真实原因是 `body` 设置了固定 `min-width: 320px`：当 320px 浏览器还要为纵向滚动条保留空间时，页面实际内容宽度只有 305px，固定最小宽度把页面撑到 320px。旧样式的浏览器回归明确失败为 `scrollWidth 320 > clientWidth 305`。

长文压力样本还暴露了两个独立风险：无自然断点的英文标题和列表文字会扩大内容盒；表格与代码块需要在自身容器内滚动。

## 具体修复

- 移除 `body` 的固定最小宽度，并让页面、网格和弹性子元素可收缩。
- 图片、视频和 SVG 不超过容器；卡片明确使用 `width: 100%` 与 `max-width: 100%`。
- 分类与日期行允许换行；标题、摘要、长 URL、长英文标识符可在必要处断行。
- 表格和代码块只在自身范围内横向滚动，不扩大整个页面；测试会识别并允许这种受控滚动。
- 320px 下正文、列表、引用、图片占位、表格、行内代码和代码块均未撑开页面。

## 首页与卡片调整

移动端 Hero 上下留白从桌面节奏收紧为 44px / 48px，内部间距缩至 26px；主标题、字幕和介绍文字同步收敛。推荐区起点在常见手机视口约 416–436px，处于普通手机首屏内。移动端区块间距、标题区间距、卡片内边距和元数据底部间距也相应缩小；桌面端仍保留原有留白方向。

## 剩余问题与上线判断

未发现仍会阻断布局、内容隔离或静态构建的视觉问题。当前没有正式文章，因此首页和文章列表显示真实空状态，这是预期内容状态，不是缺陷。

代码层面已达到生产前验收标准；但目前仍不得公开上线。ICP备案尚未完成，`PUBLIC_INDEXING` 默认关闭，服务器 SSH、Nginx、DNS 与 HTTPS 也需要备案后由管理员人工配置和验证。
